## 目录职责
- apps/planner：两张画布、对象详情、设备编辑器、情景比较和方案导出。
- packages/domain：物品、设备、资源、工序、厂房、供应关系的共同类型。
- packages/simulation：物品变化、时间推进、齐套、容量、人工占用和运输。
- packages/module-kit：九类清单、类别表单、能力/样例检查与采用；人工/Agent共用定义和实例编辑命令。
- packages/presentation：插图／图片序列、动图、三维模型和原生部件、时间轴标签及三档精细度；不拥有库存或生产时钟。
- modules：按类型存放可贡献模块，每个模块独立目录；清单索引定位。
- scenarios：可编辑的整厂与跨厂场景，输入参数和预期现象。
- community：贡献指南、模块提交和维护规则。
- .github：Issue与PR模板，不假装已建立社区运营。
- docs：阶段、契约、比赛证据和开发导航；大幅AI预览继续放上级设计预览。
- tests：核心仿真与场景测试的后续实现位置；当前只有测试任务说明。
- tools：场景和模块检查工具的后续位置，不存放机器私密配置。

每个阶段交付一个可演示闭环，避免把全套工业仿真一次性做完。没有实现的目录以README说明职责，不用空API冒充成果。
