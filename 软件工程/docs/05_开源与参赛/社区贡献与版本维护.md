# 社区参与：有用的提交怎样成为可采用版本

状态：产品治理设计。社区入口以本地模块库和仓库Issue/PR为主，不创建账号市场，不编造贡献者或组织支持。

## 不同人能交什么

设备作者提交明确端口/配方/资源和表现；素材作者提交许可明确的图片/动图/原生部件；工艺作者提交规则与专业范围；模板作者提交完整输入、连接和实例化政策；使用者提交有具体输入的失败/需求；核心维护者维护共同对象、时钟和接口消费者。

新增贡献按已有九类资产分类。只有素材、标签或模板的贡献也可以独立有用，不要求重写核心或先掌握全部专业算法。物品、设备和方案结果不因来自不同作者就生成另一套库存。

平台以“用户能够补自己所需的工厂能力”为社区目标：九类均有自己的创作与Agent入口、示例输入/输出、支持范围和版本说明。厂房/组合作者可从空工程交出布局/端口/物流分工，物品与资源作者可交规格/角色/日历，专业作者可补提供者，使用者可用自己的仿真问题提交需求。并不要求所有贡献者都是设备程序员。

## 从提案到采用的状态

|阶段|必须拿得出的内容|可对使用者说什么|
|---|---|---|
|设计提案|完整任务、输入输出、支持范围、预期及许可待补|可阅读/讨论，不能叫运行已验证|
|可编辑示例|实际设备/模板文件、可重开说明、明确缺项|文件可编辑；实际运行证据另列|
|运行验证候选|实际版本、输入、操作、输出和已知失败|说明哪项运行通过，不外推到现场|
|可发布版本|所选范围复现、贡献者/维护者、许可及采用说明|该版本可按列明条件采用|
|暂停维护/弃用|最后适用版本、原因和接手条件|已有工程仍按原版本，不自动更新/删除|

维护者检查实际贡献责任：行为变更需要同条件结果或实际失败；表现变更需要对应状态/锚点/标签和同一行为；模板变更需要端口、物料、资源及导入/交接；专业代码需要明确工具输入/结果/范围与许可。当前手算脚本只算设计证据，不能作为运行发布证明。

## 版本与使用者

新版本不自动改变已有工程。端口/单位/配比/资源/阶段变化列清影响；显示文字改名与稳定ID变更分开。失去维护不删除工程正在用的旧包，缺外部依赖时说明不可用范围。

代码拟采用Apache-2.0，实际发布需在真实代码根目录落实并核对所引依赖。素材/模型/字体/数据分别按实际文件授权；拟议代码许可不自动覆盖它们。许可未确认的私有素材留在私人包或替换位置，不附公开贡献包。

## 责任与反馈

用户本人负责全项目、共同工程整合与最终验收/发布；[本机窗口分工](../04_开发与验收/本机并行窗口计划.md)只划分AI辅助工作流及写入范围。模块维护人由真实贡献者确认后列出。目前无外部维护人员承诺，不承诺机构支持或虚构响应天数。维护分三条直接队列：使用故障、能力需求、发布/采用；使用者能看到当前是否有负责人和正在处理什么。

维护者合并前让贡献者补必要缺项，保留未支持边界；发布后根据实际反馈修正同一版本适用说明或发布新版本。争议在Issue说明任务与证据，不用比赛获奖替代技术审查。文件里只设计模板，不自动向外提交、发消息或发布。

## 比赛需要拿出什么

以真实可执行贡献任务说明开放价值：贡献一个物品素材、给设备换原生外观、完善标签/阶段、制作三类模板变体、增加受支持专业成果消费者、修正一个有输入可重现的问题。展示从提交到另一工程采用的资产与步骤。

新项目展示已落实的格式、规则、示例和维护责任；社区人数、下载和运行规模据实填写。当前这些是设计/文件成果，正式比赛录屏与发布版本由P5-01完成。

首版贡献演练须逐类验证定义可编辑、按范围检查、导入另一工程并明确采用；九类样例中各选一个最小任务，不把素材预览伪装成物理求解。保存原模块版本、作者/许可和失败限制后，再由维护者决定可发布状态。Agent可完成草稿/样例/说明准备，Issue/PR与发布按人的授权进行。

报告章节和PDF/HTML/CSV/JSON输出器的贡献走核心软件PR；工厂参数和业务能力仍按九类模块提交，不额外创造第十类。评估文档应保留采用模块和输入条件，让别人能判断适用范围并从工程继续复现。

## 现行主线在本文件的责任

社区可贡献industry/product/site适用配置、直线/U形/并行布局模式、九类角色绑定和来源明确参数示例；generation_profile是templates可选载荷，旧静态模板仍有效。贡献必须带可编辑资产、可执行范围和样例；Agent导入并采用指定版本，不自动发布。
