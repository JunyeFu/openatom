## 目标与证据层

继承已写的3厂房/60固定设备/3000件、中位FPS≥30、响应p95≤200ms、目录保存/打开各≤3秒；仅补可执行环境/采样/起止/判定，功能/21任务/18操作与S03-01正文不变

数字是既定验收目标。10秒预热、60秒采样、3轮、每类100动作和5次存取是本轮明确的测试协议，不是实测表现、行业统计或工期安排。数学例只检查统计/负载推导。实际工程、固定模型与实际GPU/候选版本须后续取得，缺失不能写运行PASS。

## 固定负载与测试条件

NFR-B60：3个厂房，6条独立串行线，每线10个容量1的固定工位、500个独立身份；工位耗时2仿真秒、交接0秒、逻辑缓存不限制，身份保留。balanced每厂20设备，dense第一厂60、其他0；两者仍3厂房/60设备/3000件。

自建基准单线首件20秒、末件1018秒；600秒共1746件接受，1200秒共3000。该软件负载没有行业产能含义。实际画面选择一个厂房，不将后台设备或代表动画数量冒充同时呈现数量。

参考画布为CSS1920×1080、DPR1、Windows100%缩放。固定详细/简化/区域素材，实际记录面数/贴图/字节/绘制调用；详细模型遵从已认可P3-02视觉要求，不用纸片或删对象达标。实际记录GPU/加速/会话、候选/WebView2和背景工作。只读机器库存为Windows11、7800X3D、约32GB，并列GPU含RTX4080SUPER与虚拟显示驱动；实际渲染适配器当前未知。

3. 取得浏览器Frames/实际帧呈现证据及正确画面截图；rAF及render提交样本只作诊断，不能独自代真实画面证据

**测量：**10；60；3；各有效轮正确场景呈现帧间隔Δt的instantaneous_fps=1000/Δt，按偶数取中间两值均值计算median；不把1000/median(Δt)当同一公式；实际候选的浏览器Performance Frames时间轴（同一时钟）；帧是否含完整目标场景由对应帧/截图核对；无足够呈现时间证据则not_evaluable；['FPS分布', 'frame_interval_p95_ms', 'dropped/partial frames', 'invalid/hidden-window intervals']；True。

**通过条件：**30；每个要求条件的3个有效轮均达到≥30FPS；原目标是中位数，不声明最差帧达标；无实际呈现证据不写PASS。

**边界：**FPS meter或rAF回调可以辅助定位；空帧、隐藏画布、关闭正确渲染、删设备/物品或降低已认可模型质量均不构成有效基准。诊断trace的开销与采样条件须记录。

## 统计、可见反馈与不合格条件

响应p95取nearest rank：排序后索引ceil(0.95×n)−1；每类/每轮n≥100，分别判。FPS取每个真实帧间隔的1000/Δt后求中位数，偶数取中间两值均值。目录存取是每个样本≤3000ms，不是平均数或p95。原始/失败/无效条件保留；隐藏窗口、缺画面证据或环境缺项不算有效PASS。

rAF回调发生在重绘之前，不能独自证明预期场景已呈现；Renderer单调计时不要和native时钟时间原点直接相减。实际画面、输入/修订及Frame证据须关联，后端返回只是UI可见响应的中间点。

## 阅读依据与原文范围

- [MDN performance.now](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now)：Description / Performance.now vs Date.now, lines208–214；performance.now uses its time origin and monotonic time; document/renderer timing must not be subtracted directly from unrelated native clock origins.
- [MDN requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)：opening description lines183–184 and timestamp lines209–212；callbacks occur before repaint and may pause when hidden; callback cadence alone is not proof that the expected complete scene was presented.
- [Chrome DevTools Performance features reference](https://developer.chrome.com/docs/devtools/performance/reference)：Analyze FPS / Frames section lines581–606; screenshots lines665–673；Frames distinguish idle, presented/partially presented and dropped frames; use frame evidence/screenshots when assessing visible response and scene FPS.
