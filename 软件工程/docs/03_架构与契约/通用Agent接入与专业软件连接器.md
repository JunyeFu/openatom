## 参考专业软件的实际接入模式

|参考|原文确认的机制|本项目采用的设计原则|
|---|---|---|
|Unity Editor|官方文档允许自定义检查器、编辑窗口和属性呈现；本机Unity-MCP指南按对象/编辑状态、命令、编译与画面反馈组织操作|先读取真实对象和能力，再执行命令，随后读结构/渲染/结果；插件不另造工程|
|Blender|官方仓库Python API文档说明bpy.data管理场景/网格等数据，Python可创建工具、UI和订阅数据变化；数据创建进入宿主管理|模型数据、操作和画面分开；可编辑资产由宿主持有，Agent不靠鼠标猜状态或自建另一套库存|
|FreeCAD|官方Addon模板有命令、工作台、GUI入口、package.xml及代码/素材许可文件|扩展带身份、版本、入口、输出范围及许可；保留结构成果，不把一张渲染当工程|
|MCP|公开规范提供工具发现及输入/输出schema；stdio是本地子进程传输，另有Streamable HTTP|首版stdio提供实际工具；通用API语义独立于传输，后续HTTP仍复用操作层|

这是由原文作出的架构选择，不声称三款软件原生使用同一种MCP，也不声称当前已连接它们。Blender文档站详细页读取失败后，核读其官方GitHub文档源码；没有绕过权限。

## 首版链路和唯一状态拥有者

```text
人工界面 ── Tauri invoke ──────────────┐
外部Agent ─ MCP stdio桥 ─ 本地宿主IPC ─┼─ 共同Rust Commands
受支持插件/专业提供者 ─ 类型化调用 ────┘       │
                                         ├─ Domain/编辑事务
                                         ├─ Simulation/唯一运行状态
                                         ├─ Packaging/实际专业成果
                                         └─ Presentation渲染请求/反馈
```

桌面宿主维护当前工程和唯一Engine。外部Agent启动的MCP进程只负责协议与连接，不能再加载一份独立库存。Windows首版用限当前用户的本地命名管道连接已打开宿主；由宿主明确授权工程/草稿范围。不存在宿主、未选工程或无能力时给出具体错误，不自动选择另一工程或偷偷启动另一仿真。

调用在共同命令入口序列化，编辑带base_revision；用户/Agent同时修改时陈旧编辑返回RevisionConflict并重新读取，不能覆盖当前工程。渲染在WebView侧执行，图像返回scene_revision/对象ID；Rust核对所需修订，不能返回上一帧冒充本次草稿。专业和生产长任务各有TaskHandle/进度/结果，取消不当成功。

## 统一能力而非一客户端一实现

[命令目录](../../packages/commands/command-catalog.design.json)是拟议单一操作定义；实际MCP tools/list只公布已实现能力，不把目录中的planned动作全部注册为成功工具。核心动作、输入输出与错误由[操作契约](首版类型格式与操作契约.md)定义，Tauri与MCP映射同一操作。

- 只读：能力、上下文、指定对象、渲染、运行状态与结果。
- 写草稿：物品/设备/资源/连接/订单/供货、原生外观、阶段和标签；批处理一次采用并列出变更。
- 计算：明确的隔离周期、全厂方案与纸包装作业；返回实际结果及范围。
- 文件：用户选定工程内的导入/保存/导出；允许资产引用不等于任意磁盘读取。
- 九类创作：按category读写定义、实例与绑定，提供该类别的预览/样例；同一apply_commands支持物品、固定设备、资源、任务、工艺、物流、厂房/组合、计算提供者与表现素材。只发现设备操作不算九类接入完成。
- 评估交付：读取真实RunId/比较与指标口径，通过export_evaluation导出PDF/HTML/CSV/JSON；没有运行结果只准备设计说明，不能让Agent编造生产数据。
- 认可：专业成果的人工决定独立，Agent默认只能提出草案/候选，不伪造用户身份或现场批准。

stdio读写遵MCP协议，stdout仅为协议消息。MCP版本按实际选用SDK和客户端协商，不将已核读的2025-11-25版本说成当前所有客户端都支持的唯一最新版。用户现有Agent的具体客户端配置在实现后真实验证；不承诺任意AI客户端无需配置即可连接。

普通编辑与彩排离线，外部Agent自己的模型连接由其客户端承担。不内置收费模型API、自动下载本地模型、修改全局MCP配置或对外上传整厂工程。用户明确提供给Agent的选择/草稿/预览才进入相应外部模型上下文。

## 三个真实业务工作流

工厂作者的首版能力现在包含**一句话目标驱动生成**，不是仅预留API：读取行业/日产目标与长宽高→query_module_library匹配原生/导入社区模板与九类定义→按来源填参并实例化布局/连接/排期→check_factory_draft核对业务与静态场地条件→真实渲染与模拟→读取接受量/等待→有据修正或失败说明→导出报告。完整职责及“日产一万纸箱”验收见[生成规格](目标驱动厂房生成.md)。

模板可以带行业与场地适用范围、布局模式及参数来源。没有相符模板或关键参数时尽量保存草案并说明缺项；Agent不在自己的文本中伪造工厂或产量。首版支持模板填充和运行反馈修正，不因此变成任意工厂的全局最优布局/排程求解器。

1. **设备作者**：取得assemble/几何/标签能力→创建可编辑部件与端口/规则草稿→渲染→按实际图和对象修正→隔离周期→保存/采用；产出设备包、渲染与真实周期结果分别列。
2. **工厂作者**：读取产品/模板→创建设备、角色和物品连接→写来料/订单/供货→检查草案→新方案运行→按实际等待引用对象/时段解释→交出人能继续改的工程。不自动搜索无限“最优方案”。
3. **专业作者**：产品改版→建立/修改纸包装结构与过程→实际计算→看Pass/Fail/Undetermined→人认可用途→绑定包装工位→同起点重跑比较。不把盒子渲染当制造/防护认证。

三种工作流共用九类创作。工厂作者可从空工程自定义物品/资源/工艺/物流与厂房，不依赖某个设备模板；在时间轴设置排期约束后运行，跟随采购件或加工件进入总装/包装，再生成带输入条件的评估报告。社区作者可保存类别模块及样例，另一工程导入采用；准备文件与实际发布分开。

## SDK、连接器与skills的预留

- packages/commands：共同API类型、操作分派、编辑范围和结果，不再复制规则。
- apps/mcp-bridge：首版stdio适配及宿主连接；HTTP传输后置但保留同一语义。
- integrations/agent/clients：各真实验证客户端的配置样例；未知客户端不是已适配。
- integrations/agent/skills/superfactory-workflow：项目内技能草案，告诉Agent怎样发现能力并完成三工作流；未安装、无调用证据。
- integrations/professional-plugins：Unity/Blender/FreeCAD连接器契约。设备/表现提供者回传GLB或原生场景、单位/坐标和源引用；CAD提供者回传真实工程成果及支持范围。首版不实现三个连接器或加载用户上传的任意脚本。

提供者清单含id/version、宿主/API范围、输入输出schema、单位/坐标、目标能力、实际available_capabilities、许可及原资产引用。实际提供者与成果消费者分别绑定，available为空时不调用；外观提供者没有生产/专业求解权限。代码插件作为维护者审核的代码/外部明确安装提供者接入，普通设备包继续是声明数据。
