# 首版类型、保存格式与核心操作契约

状态：根据已选Tauri/Rust/React/TypeScript/Three.js形成的编码设计；不是已发布API。范围以[S02-01冻结清单](../00_项目基线/首版交付基线.md)为准：P0-03只做专业artifact/acceptance/binding/result；建设/投用/公用服务字段不成为首版必备。具体schema/API/算法仍需对应详细设计复审，不由范围冻结代为通过。核心类型由Rust维护，前端类型和边界JSON schema由同一契约生成，不由界面、MCP和插件分别定义。

## 类型与所有权

|类型|字段与语义|拥有者|
|---|---|---|
|ProjectId / ObjectId / Revision|不透明字符串ID；修订为非负整数；保存相同对象身份|domain/工程|
|SimTimeMs / DurationMs|统一相对毫秒、非负整数；工程日历映射到此参考|simulation|
|ItemType / ItemInstance / ItemBatch|规格与单位分开；单件/批次承担数量和身份，首版离散件数为整数|domain/库存|
|HolderRef / Allocation / QualityState|唯一库位/作业/运输/容器持有者；预留只属分配，质量与生命周期分别表达；具体业务规则取business-objects.design.json|simulation|
|ProductRevision / OrderLine / Route|产品/BOM/路线版本、需求/交期/接受位置；需求不是库存|工程/方案|
|DeviceInstance / ModuleRef|固定位置、所用模块版本、参数覆盖、端口与所选行为；坐标m|工程/规则|
|ResourceInstance / Phase / Job|容量、日历、资格、全作业/阶段占用、有效进度与实际作业|simulation|
|Connection|判别联合Material/Signal/Artifact，端点明确；各自单位和作用不同|domain|
|Presentation / NativeScene / Timeline|资产、部件、姿态、标签与阶段绑定；不持有库存或时钟|presentation|
|Scenario / RunId / RunResult|输入版本、观察窗；运行结果归属于实际输入，不回写下一方案库存|simulation|
|Artifact / Acceptance / ConsumerBinding|实际专业成果、对指定范围的认可、所用消费者绑定分别保存|专业/工程|
|PackageStructureJob / CheckResult|有限厚度板片mm、折带、连接、多件、成型/使用过程和制造层；Pass/Fail/Undetermined|packaging|
|TaskHandle|长计算/运行/渲染的任务ID与状态；未完成无成功结果|commands/对应执行者|
|EvaluationReport / ExportEvaluationTaskHandle|报告模式、所用方案/RunId、指标口径、输入限制和导出文件引用；同源PDF/HTML/CSV/JSON|reporting/只读结果与文件任务|
|FactoryGenerationGoal / TemplateGenerationProfile|行业/产品、数量/生产日口径、场地m、现有条件；模板参数来源、工艺/布局/角色绑定|domain/module-kit；目标不是产量|
|SiteEnvelope / FactoryDraftCheckResult|长宽高、可用区域、声明占地/高度/间距；业务/布局缺项与对象引用|domain/layout检查；不作真机/建筑认证|

Rust中各ID/单位使用有区分的类型，序列化为JSON值；时间和整件数量的公开数值限制在JavaScript安全整数范围内。连续几何使用f64、毫米与显式容差；m/mm在明确坐标转换位置换算。未知/未完成时点用null，不用0冒充。

## 日常工程与交付包

```text
工程目录/
  project.json                 schema_version、工程/物品/厂房/资源/模块引用
  scenarios/<id>.json           方案输入及版本，不带当前运行库存
  modules/<id>/<version>/       实际采用定义及包内素材
  assets/                      可带出图像/GIF/GLB/原生外观
  professional/<artifact-id>/  包装输入、实际成果、SVG和认可/绑定引用
  results/<run-id>/             所用输入、运行结果/可恢复快照（有实际运行才建立）
  evaluations/<report-id>/      选择保存的评估上下文及PDF/HTML/CSV/JSON输出
  package-manifest.json         实际包含文件与许可/依赖/缺项
```

交付为上述内容的ZIP容器，可用.sfproj扩展名；代码仓库、介绍PDF和视频按赛事另外提交。私人工程、接手包和公开贡献包沿用原授权范围，资产是否随包由实际权限决定。

JSON带schema_version；模块引用明确id/version，资产使用包内相对路径。保存以临时文件完成写入后替换目标，避免半写覆盖；这是持久化完整性所需。跨文件保存时只在全部新内容就绪后更新工程清单，失败保留原有效版本；不新增无消费者校验和系统。打开未知格式/缺引用列具体缺项，禁止静默重置库存或专业结果。

只保存工程不等于已有可恢复快照。首版普通比较从共同起点运行；从中间继续仅在完整运行状态/所用版本均可恢复时支持，否则明确未支持并从头新跑。

## 共同操作入口

统一调用结构：operation＋api_version＋project_ref＋目标ID/参数；编辑带base_revision避免Agent与人覆盖彼此。成功返回有类型的data与相应revision/task_id；失败返回code/message/相关对象及可修正字段。运行或专业长任务先返回TaskHandle，结果另读；不把尚未完成写成成功。

|操作组|输入→输出|作用|
|---|---|---|
|describe_capabilities / get_context|能力/当前工程和选择→实际支持的模式、操作和对象摘要|只读；未实现不列为可调用|
|get_object|工程、ID→类型化对象|只读，不返回整个磁盘或全部素材|
|apply_commands|修订、同类编辑命令组→新修订与对象/变更|候选设计检查成功后一次采用；不直接改当前运行|
|render_view|工程修订、视图/对象→真实预览图与对应对象/修订|读取表现，不能冒充仿真或专业验证|
|run_scenario / get_run|已明确采用的输入、观察窗→任务/实际状态与结果|共同引擎执行一次，运行保存不可混入新方案|
|compare_runs|多个实际RunId、同口径指标→差异与适用条件|保留共同起点，缺结果不能计算效果|
|compute_packaging|专业输入/版本/预算→任务及实际候选/几何/过程检查|生成成果，不自动认可或增加成品|
|adopt_artifact|成果、明确认可范围、消费者→绑定与受影响对象|用户认可仍独立；Agent草案不是现场或专业人员批准|
|import_package / save_project / export_package|明确文件/目标目录/包类型→文件引用与缺项|共同边界检查路径/引用/格式；不导入任意执行脚本|
|export_evaluation|报告模式、方案/RunId、指标范围、格式与目标位置→任务及评估文件引用|读取同一结果，不再运行仿真；无RunId只导出设计说明|
|query_module_library|类别/行业/产品/场地及来源范围→模板与九类定义候选|只读实际库、版本、范围和未支持项，不自动安装任意代码|
|check_factory_draft|工程修订、生成目标、检查范围→引用/业务/静态场地结果及缺项|读取实际草案，未判定不能当布局通过；真实产量仍由模拟计算|

编辑命令的判别联合包括：建立/修改物品与产品，新增/移动/配置设备与线组，绑定资源和物品角色，连接material/signal/artifact，设置订单/到料/供货，修改原生部件/媒体/时间轴/标签，采用指定模块版本。动作只调用已实现域操作；不能提供绕过规则的set_stock或任意代码执行工具。

九类定义草稿均可经apply_commands编辑对应载荷，随后明确采用实例/绑定；模板包含厂房/产线/区域组合。专业类别可编辑输入与提供者定义，实际计算仍仅调用已实现提供者。报告类型及四格式输出见[报告契约](评估报告与数据导出.md)。

生成模板通过import_package/apply_commands实例化并填充，不另造一套生成器库存；完整目标→布局→模拟→修正→报告语义见[目标驱动生成](目标驱动厂房生成.md)。本页新操作仍planned，输入/输出的完整Rust字段及schema在详细设计中落实，不以接口目录代替实现。

真实调用方和工程授权由宿主上下文确定，不相信参数里自报“管理员”。MCP桥、界面和专业连接器消费同一命令目录；详见[接入设计](通用Agent接入与专业软件连接器.md)。
