# 工业模拟评估报告与数据导出

2026-10-13。状态：首版设计，P2-03/P2-06/P5-01待实现；不是已生成的软件评估结果。承接[S01-01平台主线](../00_项目基线/用户任务与产品边界.md)，对应SF-16。四种格式是本项目的交付选择，不宣称赛事或所有工业行业强制要求。

## 用户获得什么

用户在自由画布搭建产线，按时间轴设排期，实际模拟并比较后，选择评估问题、方案/RunId、时间窗、接受位置、指标和导出格式。软件从同一结果生成可读报告与可分析数据；Agent也调用同一个导出操作。导出的报告供评审，工程包供继续修改，两者都可以交付。

Agent按行业/产量/场地生成的工程还附：原始目标、生成模板和九类版本、场地/产品单位、参数来源/假设、所检查布局条件、初始规模理由、每次实际RunId/修改、目标与实际接受差额和停止原因。算法生成的设备数量不当已购买资产；没有完成模拟只形成设计说明。软件性能如未实测保持未知，不用生产吞吐替代FPS/计算耗时。

|格式|用途与首版内容|边界|
|---|---|---|
|PDF|固定版面评审：目标/输入、厂房和产线图、排期与实际轨道、产出/交付、等待、变更比较和限制|可阅读/打印，不能代替可编辑工程；图由当前软件渲染及结果生成|
|HTML|离线查看：同样内容、可筛选指标/轨道及按物品经历查看；所需数据/样式随报告携带|报告交互只浏览导出时的结果，不运行新方案或依赖在线模型服务|
|CSV|产出、订单、资源区间、事件、等待和方案指标等分表，用于表格工具再分析|每行带工程/方案/RunId、对象、时间参考和单位；不同单位/接受口径不能合并成一列总量|
|JSON|带schema_version的结构化评估数据：上下文、指标、事件/轨道、逐件关系、比较与限制|供Agent及其他工具读取；不是可恢复快照、工程保存格式或任意代码包|

四种格式必须同源；展示精度不改变基础数据。CSV及JSON保留基础单位和未知值，PDF/HTML的格式化读数只用于阅读。结构/制造SVG是专业成果的另外一项输出，.sfproj是工程交接容器，都不冒充评估报告。

## 同一份报告的组成

1. **评估问题与范围**：哪份工程、哪个方案、模拟起点/观察窗、目的接受阶段、产品/订单、涉及厂房和未展开的外部边界。
2. **建模输入**：BOM/路线、设备/资源/班次、工时/到料/运输、质量规则、专业成果与认可；列示例、已提供输入、待补条件及所用模块版本。
3. **画布与排期**：导出时的厂房/产线布局、物品连线、计划约束和只读实际轨道；设备图片/模型表现与行为结果分开。
4. **模拟结果**：观察窗接受量、未交量、已完整订单的完成时刻、在制/在途、资源占用与可用日历、等待条件。计算沿用[指标口径](../01_业务需求/指标成本与决策口径.md)，不另造指标引擎。
5. **逐件经历**：从外购或加工入口，经准备/总装/检验/返工/装盒，到接受位置；组成与箱内关系保持。跟踪特定零件时说明其在装配体/容器中的身份，不把已消耗部件再计为自由库存。
6. **方案比较**：同起点/同观察窗的输入变更与结果差异；交付口径、需求或范围不同则分列，不强行报改善百分比。
7. **结论与待补条件**：已观察到的阻断、输入依赖、未支持过程、缺少数据及下一步可修改条件。成本无输入时不输出总成本；没有现场验证不写真实工厂准确率。
8. **复用和附件**：模块/专业成果版本、随附资产许可、数据文件和可另附的工程包；不带凭据、未经允许的行业原文或私有素材。

## 设计说明、模拟评估与现场证据

- 无实际RunId时允许导出**设计说明**，结果字段为空，不创建假RunId、产出或改善量。
- 有软件真实运行结果时导出**模拟评估**，它是所声明输入和模型下的结果，不自动变成现场生产观测。
- 有另行取得的真实现场记录时可以作为注明来源的对照附件；没有就保留未验证。

使用者可以选择章节和指标，但不能移除工程/方案/输入版本、时间参考、单位、接受口径、结果类别及会影响结论的缺项。专业结果Pass/Fail/Undetermined原样保留，不由报告文字重新判定。

## 模块责任与操作

`packages/reporting`读取工程和真实结果，组织统一EvaluationReport，再由PDF/HTML/CSV/JSON输出器排版/序列化；只读共同状态，不运行第二份仿真或修改库存。画布图由presentation提供带修订的实际渲染。导出用户选定的目标目录，失败返回具体文件任务错误，不覆盖有效工程。

`export_evaluation`接受工程/修订、报告模式、方案与RunId、指标范围、格式和选定位置，返回ExportEvaluationTaskHandle，完成后取得文件引用、格式、结果来源和缺项。人工菜单和Agent用相同命令，实际能力未实现前不会出现在可调用工具清单。

目录契约见[reporting规格](../../packages/reporting/evaluation-report.contract.design.json)，共同操作见[命令目录](../../packages/commands/command-catalog.design.json)。本页冻结交付语义；详细Rust类型与格式生成实现仍需对应详细设计和运行验收。

## 首版验收

同一真实运行/比较导出四种格式，接受量、完成时刻、资源区间及缺项一致；另一目录可离线打开HTML/CSV/JSON和阅读PDF。没有RunId时只能输出标识明确的设计说明。选零件、改排期、重跑后，报告必须属于新RunId，旧报告保持原输入归属。Agent真实导出与人工菜单输出遵循同一口径。

报告贡献可通过核心仓库提交章节/输出器改进或有真实输入的Issue；它是平台交付能力，不新增第十类生产业务概念。九类社区资产的版本与许可是报告内容，不因导出而自动发布到社区。

## 目标生成的交付分支

目标、实际接受量与单位分别列出。初案输入齐全、检查通过且实际达标时，一次真实运行即可形成评估并保存工程；修正RunId和比较结果允许为空，修正原因列表为空，不为报告补造第二次运行。不足时在许可变量内有限修改/重跑比较，报告才引用新旧RunId及变化原因；不能修正时保留缺项/不足及停止原因，不给达标结论。无实际运行仍只输出设计说明。
