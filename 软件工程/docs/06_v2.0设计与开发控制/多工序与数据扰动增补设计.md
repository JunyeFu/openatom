# 多工序与设备数据扰动增补

2026-10-27，用户选择多工序生产、数据扰动与自动改派。原2.0.0运行包与证据保留，增量仍归V2-03/04/05/06/07/09/10/11；当前先实施V2-05。

## 用户任务与独立预期

两道相连工序，各两台替代设备，十二件投入、24个逻辑作业、十二件最终接受；工时采用可信10/15秒软件设备配置，新场景截止240000ms。原六件/120000ms用例不改。先完成工序一再消费实际中间库存；中间产出不计最终接受。四台设备只能执行自己工序的精确模型/端口/资源绑定。

正常组与维护/恢复组独立运行。维护在设备原命令Started后施加到可信设备进程，Host人工允许仍为true；原命令完成，后续未开始作业自动分给同工序替代设备。恢复必须得到真实新鲜的设备观测，才能再接新单。任何Started或执行未知的命令仍保持原身份与预留，不能因扰动重复生产。

## 结构、接口与算法

- `packages/simulation/src/external.rs`：候选按operation_ref及实际编译后映射到原逻辑作业；保留逐工序单阶段，接通原predecessors。终端作业数量核对最终目标，绑定覆盖所有工序；发令前校验真实前驱完成及Stock可用性。仍只在合法Completed回执后提交同一Engine业务效果。
- `packages/commands/src/execution_session.rs`：只给原逻辑作业比较兼容候选，保留新鲜观测、设备自报、人工允许、未决命令及资源条件；沿用预计完成时刻/稳定ID排序。等待前驱与物料需要明确原因，不把不兼容工序列为可接单。
- `host_execution_preparation.rs`、`execution_setup.rs`、`execution_runtime.rs`：取消演示硬编码的“必须恰好两台”；仍验证精确私有配置、设备唯一性、可信profile和实际编译覆盖。云draft11身份、命令、回执字段不改。
- `virtual_device.py`、`device_process.rs`、`execution_runtime.rs`：维护状态独立于Host接单开关；Native只控制自己当前会话的可信子进程。设备继续发送实际probe观测，保持原命令完成与停机结清语义。不会从Renderer提供脚本/令牌/进程路径。
- `project_api.rs`及云面板：维护/恢复是明确标识的软件设备操作，仅当前本机有控制资格的来源可请求；归档/其他Host来源不可控制。请求不冒充已生效，资格以实际Host接纳的新观测为准。
