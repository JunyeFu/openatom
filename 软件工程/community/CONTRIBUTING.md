# 参与贡献
可贡献设备定义、物品素材、动图/模型、人工任务、工厂模板、教学案例、文档和代码。
1. 先用Issue说明任务、物品输入输出、使用场景及已有模块差异。
2. 从[九类贡献入口](templates/README.md)选择对应类别样例；固定设备模板只用于设备。提供清单、说明、独立示例和素材授权；公开素材只使用许可允许再分发的内容。字段与消费者见[分类协议](../docs/03_架构与契约/九类模块清单与消费者.md)，目录见[索引](../modules/catalog.json)。
3. 本地预览并运行对应示例；当前实现未落地时明确标注设计提案。
4. PR附预期与实际结果、图片或录像、复现步骤和许可信息。
5. 维护者检查功能、场景和素材许可，提出修改后合并并列出贡献者。

首版使用仓库目录作为模块库；不先建设账号、支付、在线市场或虚构社区人数。后续是否需要托管模块市场由实际贡献需求决定。

外观/标签贡献和行为贡献分别说明：前者保留原行为，后者列输入、资源、阶段或结果的变化。提交指定模块版本及实例采用说明；端口改型/删除须列受影响连接，不能只提交新截图。未取得再分发权的素材不附在公开包内，列可替换位置即可。过程等待图需区分未开工、阶段边界、中断和输出待接收。完整规则见[设备创作与采用](../docs/02_交互设计/自定义设备创作与采用.md)。

模板贡献还要有物料/资源/专业范围与实例化政策，证明复制布局不会复制现有库存。发布/维护按[版本维护](../docs/05_开源与参赛/社区贡献与版本维护.md)处理；交接资料按[工程打开](../docs/03_架构与契约/工程交接与打开.md)处理。文件检查/手算不能填为已运行验证。

物品贡献不带现实库存，资源贡献不带当前占用，任务贡献说明准备/维修的完成作用，工艺规则说明唯一行为来源，专业贡献区别计划能力与实际提供者，素材贡献声明锚点角色和使用者映射。当前21份清单都是设计提案；发布状态由实际实现、复现和许可决定。
