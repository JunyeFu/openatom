# 有界 Agent 联验

复用桌面的 Host、MCP bridge、`ExecutionWorkflow` 和原 SDK。本入口不部署生产服务，不直接写业务数据库，不执行整厂长跑。`fv1_short_chain.py` 仍用于原有 100 条遥测重放；生产短流程用 `fv2_short_chain.py`，两种结果分开。

## 输入与连接

1. 使用当前候选正常启动桌面，打开工程的可写副本。旧 Run 和旧执行会话仅供读取。需要生产短流程时，先通过既有连接导入功能配置专属测试服务；不要把密钥放入工程、调用记录或交付附件。
2. 在“Agent → 连接、权限与任务”复制当前 Host 临时连接配置，取得 bridge 路径、`--host-pipe` 和 `--host-instance-id`。Host 重启后重新读取，不沿用旧端点。
3. 以下命令启动 bridge 后，在该面板核对实际 PID 并授权当前工程所需操作。读取使用 `describe_capabilities`、`get_context`、`get_object`、`get_run`、`read_cloud_production`、`read_execution_view`、`get_execution_snapshot`、`get_task`；执行另需 `start_execution_session`、`control_execution_session`，保存另需 `save_project`。不授权 Gateway 私有操作。初始化等待预算内未授权会明确退出，不自动重连。
4. `project-id`、`scenario-id`、修订均取实际工程；`policy.json` 是操作者明确选择的完整 `ExecutionPolicy`。保留真实目标、接受窗、截止、结算策略，不能为了短流程把完整目标改写为已达标。

准备完成会改变 Host 可用能力，入口会重新读取真实 catalog 和 `tools/list`。允许调用 H03 操作也不等于授予某个执行会话的具体动作；H02 的 `allowed_session_controls` / `device_acceptance_control_ids` 必须实际包含所选动作/设备。当前 Native Agent 面板的普通操作选择尚不能代替 Host 的执行级授权。没有这层授权时，入口明确拒绝控制，不能按 Agent 已运行/停止计通过。

在源码的 `软件工程` 目录运行（Python 3.11+，仅标准库）：

Windows 候选附带的 `agent-entry` 保留同一目录结构；使用候选时先进入该目录，再执行下面的相对路径。`$bridge` 指向候选根目录中的实际 bridge，不指向源码或其他包的可执行文件。

```powershell
$bridge = '候选目录\superfactory-mcp-bridge.exe'
$pipe = '当前 Host 提供的管道'
$hostId = '当前 Host 实例'
$project = '实际工程 ID'
$scenario = '实际方案 ID'
$scenarioRevision = 1 # 改为实际值
$connection = @('--bridge',$bridge,'--host-pipe',$pipe,'--host-instance-id',$hostId,'--project-id',$project)
py -3.11 tools/cloud/fv2_short_chain.py inspect @connection --scenario-id $scenario --scenario-revision $scenarioRevision --output results/inspect-01
```

`inspect` 只读实际配置、问题和候选绑定，不准备或启动生产。核对 `configuration.json` 后再运行：

仅准备新身份、暂不开始生产时：

```powershell
py -3.11 tools/cloud/fv2_short_chain.py prepare @connection --scenario-id $scenario --scenario-revision $scenarioRevision --policy policy.json --confirm-prepare --output results/prepared-01
```

H01 完成后保留 `identity.json` 和 `frozen-inputs.json`。准备不会自动开始生产；连接关闭后新连接仍需独立授权，不能继承旧连接的执行级权限。准备状态未知时先恢复原请求，不再次准备。

准备并明确授权执行完整有限流程时：

```powershell
py -3.11 tools/cloud/fv2_short_chain.py execute @connection --scenario-id $scenario --scenario-revision $scenarioRevision --policy policy.json --confirm-prepare-run-stop --run-seconds 10 --wait-seconds 60 --maintenance-device '实际设备 ID' --save-selection-file current-save-token.json --output results/short-01
```

该命令明确授权一次准备、开始、限时观察、设备停止接单及恢复、停止派发；不需要维护时省略 `--maintenance-device`。维护前后各观察 `run-seconds`，最终停止后最多观察 `wait-seconds`。所有控制使用新读的实际 R；冲突会退出供重新决策，不自动重发。计时只限制观察与停止派发时机，不代表生产目标已达成。

如果 H01 已明确完成且原会话仍是当前 Host 的 `prepared`，后续授权补齐后可以沿用它，不再准备一次：

```powershell
py -3.11 tools/cloud/fv2_short_chain.py resume-prepared @connection --identity results/short-01/identity.json --expected-inputs results/short-01/frozen-inputs.json --confirm-run-stop --run-seconds 10 --output results/continue-01
```

这不是未知控制的重试：入口先读实际状态，只允许当前 Host 的原 `prepared`；已经 running、旧 Host、不同冻结输入都拒绝。若执行控制由 Native 操作者完成，Agent 使用只读观察入口，保持控制来源明确：

```powershell
py -3.11 tools/cloud/fv2_short_chain.py observe @connection --identity results/short-01/identity.json --expected-inputs results/short-01/frozen-inputs.json --await-terminal --wait-seconds 120 --save-selection-file current-save-token.json --output results/observe-01
```

`observe` 不发开始、停止、维护或取消；Native 操作者按既有界面执行这些动作。等待正常停止时，还要等待原执行的发布确认同步，不能在 `publication_pending` 时宣称最终保存范围已经稳定。普通保存 Task 的 `originating_request_id` 是可选字段；入口始终核对原 Task 的 ID、操作、scope、kind 和冻结修订，字段存在时额外核对原请求 ID，并要求实际保存结果 `still_dirty=false`。任务完成后若 Host 又产生了新内容，关闭保护仍可能提示未保存；先核对新内容，再明确保存新的范围，不把旧 Task 改写为失败或自动重投。

保存令牌文件启动前必须不存在。命令打印实际连接 context 后，在 Native Agent 面板选择这个连接、用途“保存可编辑工程”、系统目录选择器选定新目录，再把“复制目录令牌”的完整 JSON 保存到 `current-save-token.json`。文件只传递 Host 发放的本连接令牌，不能填磁盘路径、猜 ID 或复用其他连接令牌。`save_project` 完成后才记保存成功。目录令牌和含本机身份的完整调用记录用于受控复现，不放进公共示例工程。

## 正常关闭和新进程读回

先核对 `status.json` 的实际生命周期及未结清义务，再通过桌面正常关闭。启动新的桌面进程，打开刚保存的工程，重新复制连接参数并授权新连接。原身份来自前次 `identity.json`，只读恢复：

```powershell
py -3.11 tools/cloud/fv2_short_chain.py readback @connection --identity results/short-01/identity.json --expected-inputs results/short-01/frozen-inputs.json --run-id '实际旧 Run ID' --output results/readback-01
```

这里的 `$connection` 必须已更新为新进程端点。`readback` 不调用准备或控制；原会话身份保持，只比较原冻结输入并读实际状态。要核对旧 Run，在 execute 和 readback 两次命令均传入对应 `--run-id`，保留两次 `old-runs-before.json` 再逐值比较；单次运行的 `old_runs_unchanged` 只证明该次读取前后相同，不能代替跨进程比较。

## 输出与失败定位

- `calls.jsonl`：实际 canonical 请求和 Host 响应；`bridge.stderr.txt`：bridge 错误。stdout 非协议文本、断线、超时、响应 ID 不同均结束连接，不重投业务请求。
- `context.json`、`catalog.json`：实际 Host、调用者、工程和能力；`configuration.json`：实际配置/问题；`prepared.json`、`identity.json`：本次新准备结果。
- `frozen-inputs.json`：原冻结输入；`status.json`：本次完成标记、错误、最后真实快照、义务及原 pending 请求。保留请求未知、失败、取消和未结清的差别。
- 超时不是业务 Task 失败。未知原请求不得再次准备；原连接仍可用时沿用 `ExecutionWorkflow.recover()` 查询。新连接须重新授权，知道原 Task ID 时可通过面板共享确切任务；旧调用者的请求登记不能假定可跨连接查询。保存请求的原始关联也保存在 `calls.jsonl`，不要重新保存来掩盖未知结果。
- 成功退出表示选定步骤完成；实际输入、执行、产出、运输和业务数量须从保存的 Host 快照逐项核对。未观察到的业务环节不能仅凭退出码判通过。

服务端口、数据库和配置沿用测试环境实际配置，先核对所有权与空闲端口。现有 `local.py` 默认 HTTP `127.0.0.1:23270`、专属 PostgreSQL `127.0.0.1:23271`；Native 的 HTTPS 要求沿用既有入口，不把 HTTP 组件检查称作 HTTPS/Native 通过。服务停止/重启由环境持有者操作，SDK 持久日志保留以验证恢复。93 端点启动定义由同一完整冻结输入及 `make_bindings.py` 产生，与本次有限路线结果分开，不提前执行整厂长跑。

原执行长任务的命令行恢复入口：

```powershell
py -3.11 tools/cloud/fv2_short_chain.py recover @connection --pending-state results/short-01/status.json --output results/recover-01
```

只接受同一个尚存的 Host 和原工程。若保存了原 Task ID，先在 Native 面板向新连接共享这一确切任务，再读取原 Task；若原 Task ID 未收到，仅查询原请求登记，`not_found` 仍保持未知并以非零退出。Host 已重启时不能用此入口把旧请求迁移为新请求，应通过已完成的工程保存件只读恢复。这里的完成标记指原任务状态已经确定；`recovery.status=failed/cancelled` 仍表示原业务失败/取消，不能当作业务成功。
